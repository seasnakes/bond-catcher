# 竞价信号：金额、走势与撮合前预警

## 本次行为

- 正股、转债各自显示涨跌幅、竞价成交额和实际采样曲线。金额显示到两位小数的万元／亿元，悬浮可读完整元数；百分位不再作为主展示。
- 09:15 起，有有效价格就可进入价格观察。走势资料足够时，增加水下拉起、持续抬升、持续回落、冲高回落等判断；09:25 前明确标为价格预警，成交额显示“待撮合”。
- 09:25 后，根据源时间和返回金额更新为撮合后观察。某些标的无数据不再阻止其他股债的观察信号出现；单边行情允许显示单边观察，不能给出联动确认。
- 进入竞价时自动切换监控面板，包括已保存“盘中信号”的页面。当天自动切换一次，之后尊重用户手动选择。面板每 3 秒请求一次，返回上限从 80 提高到 200。
- 竞价采样继续由服务端执行并持久化。采集时间改为各批返回的实际时间，避免批次耗时导致后续报价被误认为来自未来；同一源时间的新金额可以更新原采样，旧时间样本不能覆盖新数据。

## 数据与判定

链路仍是 QMT 行情 → Python `/quotes` → Node 服务端采样缓存 → `/api/auction/signals` → 看板。未改行情后端选择及交易逻辑。

金额采用 QMT `full_tick.amount`，单位元。只有源时间达到 09:25 且金额为正才作为竞价成交额；之前返回的 0 不表示实际成交额为零，也不作为虚拟匹配金额。撮合之后未返回正数金额时显示“暂缺”。金额判定使用累计竞价成交额，不再使用末五个采样的金额增量之和。

规则集中于 `lib/auction-signals.js`，接口同时返回 `rules`：

| 项目 | 初始观察规则 |
| --- | --- |
| 价格观察 | 正股涨幅至少 1.2%，转债至少 0.8%，或有足够采样支持向上走势 |
| 金额条件 | 正股至少 500 万元，转债至少 50 万元；这些是可调观察门槛，不是历史检验得出的盈利参数 |
| 走势最少资料 | 同一分析窗口至少 3 个源时间不同的点，跨度至少 30 秒 |
| 分析窗口 | 有 09:20 后样本时仅分析后段；后段资料不足则标为待积累，不借用早段强势 |
| 水下拉起 | 窗口首点不高于 -0.3%，末点不低于 +0.2%，提升至少 0.8 个百分点，净变化／累计绝对变化至少 0.35 |
| 持续抬升／回落 | 净变化至少正／负 0.6 个百分点，方向效率至少正／负 0.35；仍在水下的抬升标为水下回升 |
| 冲高回落 | 距窗口最高点回落至少 0.8 个百分点，且回落幅度不小于净提升 |
| 时效 | 竞价期间源报价超过 45 秒未更新，标记滞后，该侧不触发新的实时信号 |

走弱信号排在强势观察之后；即使撮合金额很大，后段明显回落也不会给出股债量价同步。价格、金额相近时，向上轨迹增加排序分数，回落轨迹降低排序分数。百分位只保留为接口辅助字段，不决定成交额门槛。

图表横轴为 09:15—09:25:30 的真实时间比例，竖线标出 09:20，横虚线表示昨收。超过 120 秒的采样间隔断线，分析文案同时标记采样稀疏。价格曲线使用各自昨收的涨跌幅；两图的纵轴分别缩放，不能按屏幕斜率比较股债涨幅大小。

## 竞价昨比（2026-11-09）

竞价联动在正股和转债各自的成交额下方展示竞价昨比，按「开盘竞价成交量 ÷ 上一交易日全天成交量 × 100%」计算。悬浮可查看原始成交量和分母所属的交易日。该指标只用于展示。

撮合前显示“待撮合”。撮合后的分子取有效竞价采样的 QMT 累计成交量。旧采样缺少成交量时，按证券和源时间戳匹配 QMT 竞价 tick。上一交易日由 QMT 交易日历确定，分母取该证券当天的不复权日线成交量。缺少有效成交量或分母为零时显示“暂缺”。历史数据按交易日和证券缓存，在后续轮询中补齐。
