# 小王子消息存档（第一阶段）

访问 http://127.0.0.1:5188/ 。独立于 finance 5173 服务，无自动交易或看板写入；飞书推送按文末配置启用。

## 已实现

- `web/prince/collector.js`：在益聊当前网页观察目标群的消息节点；按群名和作者昵称筛选。首次加载、翻页记录为 history，启动时刻之后的消息 ID 时间记录为 observed（页面新到，不等于低延时 IM 实时事件）。
- `scripts/prince/store.py`：SQLite 主记录和追加版本；相同 ID 内容去重，更正保留原文；事务保证坏批次不部分写入。图片签名参数变化不制造新内容版本。
- `scripts/prince/server.py`：仅监听 127.0.0.1:5188；只允许指定原站跨域 POST；媒体只允许已观察的 IM 图片主机，拒绝跳转；下载到本地后页面从本地读取。
- 本地存档位于 `~/Library/Application Support/finance-prince/`，不在仓库或 finance 静态服务范围内。
- macOS LaunchAgent `com.seasnake.finance-prince` 登录时运行并在退出后重启。它只保证数据库/网页服务常驻，不保证浏览器采集器自动恢复。

## 观察器接入

在已登录且选中“可转债技术交流群三群”的原站页面执行以下代码（开发者工具或获授权的浏览器 CDP Runtime.evaluate）：

```js
fetch('http://127.0.0.1:5188/collector.js')
  .then(r => r.text()).then(s => (0, eval)(s));
```

重复接入会停止旧观察器。停止采集：`window.__princeCollector?.stop()`。原站没有发送任何群消息。

页面必须保持打开、电脑保持唤醒。刷新页面会移除观察器；切换群会报告 wrong_channel。服务暂时不可达时，未确认入库记录保持待重试；尚未持久化到磁盘的网页记录仍可能因关闭页面丢失。页面心跳不表示源 IM 在线。

手动点击原站“查看更多”时，观察器自动保存新增历史。尚未实现全量自动分页或离线游标恢复。不要把已加载范围宣称为全历史；不要将补录记录放入实时推送队列。

## 双来源转发去重（2026-09-21 10:29 已启用）

- 文字按 Unicode NFC 和空白归一化后的内容匹配；跨来源及 MX 内重复转载的时间差不超过120秒时，复用第一条已排队的消息。益聊自身不同 ID 的重复提醒仍保留。
- 图片使用 Pillow 解码、纠正 EXIF 朝向后的尺寸与 RGBA 全像素 SHA256；动画按文件内容判断。不同 URL、元数据不影响相同像素去重。重新压缩、缩放、裁剪后的图可能重复，不能为了去重而误删发生细小数字变化的行情图。
- 去重记录 `delivery_content`、逐部分判定 `delivery_part` 与 outbox 在 SQLite 同一事务提交，重启不丢；旧发送队列先导入去重索引，已有 receipt 不重发。
- 正文先处理，图片等待下载与签名；纯图片不再附加占位文字。图片文件异常不阻塞其他正文，看板显示等待图片数量及后台 API 的 mediaErrors。

- 页面显示观察器心跳与两个来源的最新消息时间；心跳不能证明原站 IM 连接有效。
- 服务环境依赖 Pillow（当前 `/usr/bin/python3` 的 Pillow 11.3.0 已验证）。测试：`/usr/bin/python3 -m unittest discover -s tests/prince -v`。
- 回滚单源：去掉 `feishu.json` 中 `mx_enabled_at` 并重启服务；已经排队的条目仍会完成，已发送记录保留。数据库及配置在本地数据目录有 before-dual 时间戳备份。
