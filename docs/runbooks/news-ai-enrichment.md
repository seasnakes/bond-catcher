# 快讯八合一：去重与 AI 编辑方案

状态：离线预览已实现，**AI 结果没有接入实时飞书发送**。现有原文、图片和发送记录仍由 `messages.sqlite3` 与 `delivery_outbox` 保存。

## 已验证的输入问题

- 2026-09-22 的一批带图消息正文只有 `4:`、空行及字面量 `\n`。先前会额外发送一条几乎空白的文字；`news_filter.py` v5 已将其识别为图片占位符，只保留图片发送。
- 离线预览对当天 844 条存档快讯按“去免责声明、去开头时钟、规范空白及全角字符、图片 URL 去查询参数”生成精确指纹，识别 129 条重复记录。此数包含历史和过滤消息，不等于已发群的重复次数。数字、正文或图片 URL 改变时不合并。
- 两条真实长研报用本机 `codex exec` 试跑成功，分别约需 30 秒和 2 分钟。第一条虽然带有原文证据，却把“三至五年”概括为“临近”，说明结构化 JSON 合格不等于语义准确；第二条仍在摘要中复述了评级。因此研报 AI 摘要当前只能供审核。

## 推荐发送链路

```text
MX 原消息 → 原文和全部图片入库 → 空白/免责声明清理
          → 精确指纹去重（保留 duplicate_of 审计关系）
          → 普通事实快讯：原规则发送
          → 研报/长文：后台 AI 提取 → 证据、数字、标的与措辞校验 → 待核对草稿
          → 审核通过后才进入原有幂等飞书 outbox
```

1. **去重先用确定性规则。** 相同正文与图片在同一交易日只出一份，重复 ID 仍入库。改动价格、百分比、日期、公司名称、图片的消息一律当作更新保留。相似但不相同的报道只标注“疑似同事件”，不自动吞掉后续进展。
2. **AI 只处理值得加工的候选。** 优先选长于约 800 字、含研报/券商推广线索或多个来源反复转发的消息；普通短快讯仍走快速通道。建议把 AI 工作队列与 15/30 秒原站监听分开，避免模型慢调用阻塞采集。
3. **研报只提事实、假设和风险。** 要标明“某机构认为/预计”，不把预测写成已发生事实；去掉强推、目标价和交易指令。每条提炼要点必须带原文字面证据，数字、证券名必须出现在原文，后续再用行情/证券主数据核验标的映射。图片中的信息若要提取，需单独增加视觉/OCR 环节。
4. **失败时不静默丢消息。** 保存 `source_id`、原文 digest、模型、提示词版本、结果、证据、审核状态和错误。AI 超时或校验失败时保留原规则结论；不自动把未经核实的研报内容发到群。

## Codex CLI 原型

本机已登录 Codex CLI。官方支持 `codex exec` 非交互运行、`--ephemeral` 和 `--output-schema` 结构化结果，适合离线批处理或后台草稿生成：[官方说明](https://developers.openai.com/zh-Hans/docs/non-interactive-mode)。原型 `scripts/prince/news_ai_preview.py` 只读 SQLite，默认只计算去重；传 `--codex-id` 才对指定消息运行一次 Codex。执行环境为临时目录、只读沙盒，最终 JSON 还会核对原文证据、数字、标的数量和研报推广措辞。原站文本是非可信输入，正式常驻运行应进一步隔离模型进程与本机凭据。

```bash
/usr/bin/python3 scripts/prince/news_ai_preview.py --date 2026-09-22 --limit 1000 --output /tmp/news-ai-preview.json
/usr/bin/python3 scripts/prince/news_ai_preview.py --date 2026-09-22 --limit 1000 --codex-id news-158393643 --output /tmp/news-ai-example.json
```

`codex exec` 的实测用时不足以作为逐条实时推送的前置步骤。若后续要让加工消息稳定低延迟发群，可沿用同一 JSON 契约，改由受限的模型 API 工作器处理，并先进行至少数日的影子运行、人工复核及漏报/错报验收，再切换群内显示策略。
