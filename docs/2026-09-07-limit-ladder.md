# 主看板连板天梯（2026-09-16 修复）

连板天梯现在是主看板原生叠组，首次放在“小热次”后面，与热、热债、光等分组一起展示。顶部入口定位到该组；旧 `/limit-ladder.html` 自动跳回主看板，不再依赖 Tick Stock Panel 服务。

## 自动归组

- 服务启动后扫描，每分钟更新一次；相同快照不重复写入看板，已完成的历史快照可复用。保留主看板原有叠组和卡片样式。
- 盘前按上一交易日实际连板数分成“连板·昨3板”等子组。前一交易日由现有 QMT Bridge `/api/calendar/prev_trading_date` 返回，不能用自然日减一天。
- 交易日 09:30 后读取当天涨停池，按来源实际连板数分成“连板·4板”等子组；开板离开涨停池或板数变化时随下一次扫描更新。连板默认展开，首板默认折叠。板数不根据报价涨幅推算，盘中封板不代表收盘结果。
- 大 QMT 日历若暂时只到昨天，网关用对应沪深指数的当天连续交易报价、正成交额和成交量核实今天已开市，再补入当天。旧报价、盘前占位、未来时间和零成交不会成为开市依据，不用星期几猜测交易日。
- 交易日切换后替换上次自动添加的成员，保留其他板块、其他叠组、手动添加到梯队内的股票，以及已有展开选择。改名或移动导致不再能确认归属的用户内容不自动清理；遇到首次同名板块/叠组直接停止，避免接管用户内容。
- 复用主看板状态写锁，应用前重新读取最新状态。按日先备份 `runtime/limit-ladder-backups/`，原子写入看板及 `runtime/limit-ladder-board.json`。写入归属记录失败时在锁内回滚看板。
- 主来源无有效数据、空池、分页不完整、日期错误或两家同日连板数冲突时，保留原分组、原日期和原更新时间，页面显示“更新待重试”。只缺东方财富补充时，继续展示同花顺已核实数据，显示“北交待核”，后台继续重试，不能据此认为北交所没有涨停股。
- 前端每 10 秒轻量读取归组状态；服务端板块变化时自动载入。编辑、保存中或保存失败时不会覆盖本地修改，避免新债自动归组和用户编辑互相覆盖。

## 数据来源选择

主来源使用已配置的同花顺 Agent `special limit-up-pool`，按上海零点的 `date_ms` 指定交易日，完整读取 `page/size` 分页。使用 `continue_day_cnt`，保留涨停原因；价格与涨幅字段不作主看板实时行情。CLI 直接复用已有系统凭据，不在项目保存密钥，不需要额外常驻服务。

东方财富 `getTopicZTPool` 用于连板数交叉校验和北交所缺项补充；同花顺请求失败时可使用明确标注的东方财富同日备用池。两家都失败或重合股票连板数不一致时不更新分组。补充源日期不符或失败，不冻结同花顺已核实的整个天梯，而是标注覆盖缺口。两家沪深名单差异保留在快照里，不擅自合并非北交所差项。

- 同花顺日期由固定请求参数约束；其响应 `timestamp` 是组装/就绪时间，不能当交易日期。
- 同花顺连板天梯矩阵有展示数量口径，因此归组使用完整分页的涨停池。实测矩阵可能超过文档展示上限，不按该上限推算完整数量。
- 东方财富日期校验 `qdate`，数量校验 `tc`；价格 `p / 1000`，`zdp` 已是百分比。连板数用 `lbc`，不能用包含间断涨停的 `zttj.ct`。
- 当前东方财富实际返回科创板和北交所；不要沿用旧版本资料中的排除范围。
- 完整收盘底表按日期持久化到 `runtime/limit-ladder-pools-v2/`，盘中快照不能成为次日底表。进程重启可读取已验证的同日缓存；标记 `coveragePending` 的快照不会永久冻结，缓存到期和重启后仍重试补充源。
- 主看板显示数据日期、盘中/收盘/底表、数量与更新时间。鼠标停在日期说明上可见来源/覆盖；停在梯队股票上可见数据日期、板数、来源、涨停原因与行情时间。

QMT 官方提供 VIP `limitupperformance` 数据（`direct`、`sealCount`、`sealDays`、`sealBreak` 等），但当前 BigQMT 网关实测龙版传媒 09-04/09-07 这些字段全为空，不能用空字段建立涨停池。这只证明当前链路没有取得该数据，不能据此断言账号没有 VIP 权限。板块列表当前也未成功返回；不为此修改交易后端。

参考：[同花顺特色数据接口](https://github.com/HiThink-Tech/Financial-API/blob/main/docs/api/endpoints-special-data.md)、[迅投股票数据字典](https://dict.thinktrader.net/dictionary/stock.html)。

## 主看板行情

- 沪深行情继续经过现有 Python `/quotes` 与活跃 QMT 网关。原生卡片复用价格、涨幅、分时、竞价展示及排序。
- 北交所保持 `.BJ`，在 Node 层从同一 QMT 网关 `full_tick` 补充，不送入仅支持 `.SH/.SZ` 的 Python 接口。保留原始报价时间、昨收和成交额；北交所也纳入主看板竞价采样。现有北交所全天分时接口仍未接入，不伪造分时曲线。
- 盘前保留昨日梯队，开盘后以当日涨停池确认当前板数；当前报价由独立行情链路刷新，不用涨幅推算晋级。
- `/api/limit-ladder/board` 的 GET 只读取状态，`?preview=1` 只读预览；POST 为本机同源应用归组。旧历史/实时报价 API 保留，但来源已经改成独立涨停池；历史接口现在明确 `coverage=limit_up_only`，不提供断板/炸板晋级分母。
