# 可转债 AI 分析

第一版把 Finance Board 的行情快照、日线、分钟指标和条款观察组织成有来源的研究上下文，调用本机 Codex 生成报告。参考 Tick Stock Panel 的数据准备、固定提示词、任务和历史报告流程，不依赖 Tick Panel 服务。

## 交付与验收

1. 数据：读取现有日线和分钟数据库；MA5/MA10、近五日高低参考位与个债页相同；记录来源、单位、覆盖、报价时间，历史分析禁止混入未来行情。
2. 理论：用户指定的飞书《9月4日下午茶》为主要来源，预言家支撑/压力/分时/均线课程和可转债 skill 为补充。原文观点、工程观察条件、行情事实分开。
3. 模型：独立临时 Codex 环境，复用登录，纯文本生成；报告保留完整上下文、提示词版本、来源版本和模型，不访问交易接口。
4. 产品：主看板与个债页入口、数据预览、日 K 和多日分时、关注点、进度、取消、历史、提示词查看和报告下载。
5. 验收：日期与单位、缺失值、参考位一致性、分钟缺口、无未来数据、任务取消/失败/保存的测试；真实页面；一次真实 Codex 分析。连接成功不代表所有文字已经通过财务或交易验证。

## 数据边界

- 日线优先读取既有 QMT `1d` 缓存（不复权），缺失日期可由本地分钟聚合补齐，并逐行标记聚合来源与分钟覆盖。
- 分时页现有参考位来自本地分钟聚合日线，因此单独保留这套参考日线，计算分析日之前五日/十日收盘均值及前五日最低/最高价；不能悄悄用另一套数据替换。
- 本地数据库不包含成交量的分钟只传成交额（元）；不通过金额反推真实成交量。分时均价复用原有金额/分钟收盘价近似口径，明确不是逐笔 VWAP。
- 日线、分钟与实时报价分别标注时点。未完成分钟不参与确认；盘中日 K 标记为未完成。报价获取时间不代表源行情时间。
- 股债估值要求同日价格，转股价的条款时点单独披露。过旧条款、强赎观察、发行规模回退、缺失的财报/公告都要显式显示，不能补造。
- 每次组织上下文都会调用现有 `/bond-meta?code=…&date=…`：从当前配置的 QMT 网关取股债报价与正股分钟，日期不匹配时尝试指定日期的日线收盘；失败保留本地数据并显式提示。它不会启动或切换交易终端。
- 强赎表以六位裸代码查询，只接受不晚于分析日的最新观察；表是每券最新状态，不能伪造较早日期的历史计数。公告只读分析日及之前的条目，最多读取 5 页并记录正文完整性、原文链接和摘要校验值。
- 公告明确写出的转股价和生效日独立核验；评级、合同到期等基础条款不会随之自动更新。停止交易日、最后交易日、停止转股日、登记日和赎回日分别保存，公告优先于资料站含混日期。已公告强赎的执行风险在页面和报告开头突出。
- QMT `FloatVolume` 仅有当前接口观察、无历史生效日；单独提供 `capital_observation`，不得用于历史剩余规模、历史换手率或历史余额条件判断。
- 保存的报告是一份静态研究快照，不持续盯盘、不下单、不修改交易设置。
- 行情时间、北京时间的快照生成时间、原始日线与聚合补充数量由系统写入报告页首/页尾；同时保留模型原始正文，避免来源记录依赖模型转述。

## 2026-09-11 数据补全修复

- AI 入口默认最近五日，独立于个债页当前的一日图；历史报告保留请求范围，重新读取不会缩成实际取得的天数。
- AI 专用 `bond-meta?ai=1` 一次读取股债原始日线，补齐新券日 K；原有分钟聚合参考位不被替换。历史请求跳过当前 tick 和当前余额，正股可复用已保存的 QMT 分钟；每根缓存必须校验源时间，不能靠文件名推定日期。
- `cb_ai_terms.py` 读取上市公告与后续转股价变更公告，最多扫描三页公告目录、每份正文最多十五页。只有完整正文、债券代码和分析日期均通过核验才进入条款；保存公告日期、页数、原文链接和摘要校验值。
- 合同到期、转股起始、上市日期、到期赎回价、发行规模和发行时评级由公告独立补齐。发行评级不冒充最新跟踪评级；发行规模不冒充历史剩余余额。
- 初始转股价附发行生效日期；只有后续变更公告已检查至分析日，才允许超过七日的公告价继续参与估值。遇到无法解析、代码不匹配或未完整读取的变更公告，禁止把旧价当成已核验的现价。
- 系统保留真实缺口，并向模型明确新券上市前没有行情；报告不再逐段重复未接入的财报、新闻、Level-2 和历史余额。
- 模型输入将旧的 `issue_scale_billion`（实际单位为亿元）改为明确的元金额和亿元文本，避免十倍换算；修复跨月日期差的月份偏移。转股倒计时由系统计算，报告展示时核对明确标注的发行规模和倒计时，并保留模型原始正文。

## 实现

- `scripts/cb_ai_snapshot.py`：只读已有 SQLite/JSON，复用现有分钟指标计算，允许监控停止时读取历史。
- `lib/cb-ai-context.js`：数值、时间、质量、观察条件、压缩后的模型上下文。
- `lib/cb-ai-service.js` 与 `lib/codex-text-provider.js`：冻结快照、任务、持久化、独立 Codex 文本调用。
- `docs/prompts/cb-ai-analysis.md` 与 `data/cb-ai-knowledge.json`：可检查的提示词与理论摘要。
- `bond-ai.html/js/css`：研究页面；`/api/cb-ai/*` 为服务入口。

## 工程观察条件

0.1% 价位容差、连续两根已完成分钟、此前二十根分钟成交额均值等是第一版可解释的观察参数，不是预言家原文承诺的交易规则，也未经策略收益验证。间隔不连续时不确认；历史样本中的绝对成交额或股债一比一涨幅映射不直接迁移。
